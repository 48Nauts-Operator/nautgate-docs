## Quickstart (published images)

```bash
curl -fsSL https://nautgate.dev/compose.yml -o docker-compose.yml
docker compose up -d
```

This pulls prebuilt images from GHCR and starts everything — no clone, no build.
The dashboard is at `http://localhost:8090/dashboard`.

Three services, all bound to loopback:

| Service | Port |
|---|---|
| `nautgate` (the gateway + dashboard) | `127.0.0.1:8090` |
| `nautrouter` (routing sidecar) | internal |
| `nautgate-db` (Postgres 16) | internal |

### Your first API key

NautGate mints one on first boot and prints it to the log — grab it, then use it
for the dashboard and API:

```bash
docker compose logs nautgate | grep -A1 'first-run'
```

Mint more, or revoke that one, in **Settings → Keys**.

### Provider keys

Optional, and all `${VAR:-}`-defaulted so an empty config still boots. Set the
ones you use in a `.env` file next to the compose (or export them):

```bash
OPENROUTER_API_KEY=...     # enables the default auto-tier routing
ANTHROPIC_API_KEY=...  OPENAI_API_KEY=...  GEMINI_API_KEY=...
```

They reach both the router (which forwards calls) and the core process (which
runs quality judging, shadow trials and the drift investigator).

### Your own database or config

- Point at an external Postgres by setting `NAUTGATE_DB_URL`.
- Override the bundled routing/pricing tables by uncommenting the
  `./config:/app/config:ro` mount in the compose file.

## From source

To build the images yourself instead of pulling them:

```bash
git clone https://github.com/48Nauts-Operator/NautGate.git
cd NautGate
docker compose -f deploy/compose.published.yml up --build -d
```

(The compose file has a commented `build:` block per service — uncomment those and
it builds locally instead of pulling.)

<Callout>
The repo also ships `deploy/docker-compose.yml`, which is the **development**
stack — it starts only Postgres and the router, and runs the gateway itself via
`uv run uvicorn` for hot reload. That one is for hacking on NautGate, not for
running it; use the published compose above to actually run it.
</Callout>

## Backups

A `pg_dump` of the `nautgate` schema, gzipped to a persistent volume, on a
schedule you set in **Settings** (default: every 3 hours, keep the last 20). The
scheduler is local-disk only, so it keeps running in
[offline mode](/docs/operations/offline-mode).

Restore is **destructive** — it drops and recreates the `nautgate` schema.

## Exposure

Every published port binds to `127.0.0.1`. NautGate has no multi-tenant
authorisation model beyond API keys, `NAUTGATE_LOCAL_ADMIN_TOKEN` embeds a live
token in the dashboard HTML, and a key can be passed as a `?token=` query
parameter. **Put it behind a reverse proxy with its own authentication before
exposing it beyond localhost or a private network.**
