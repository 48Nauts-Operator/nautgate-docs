Everything under `/v1` requires a metered `ng_` key. See
[Authentication](/docs/reference/authentication).

<Callout>
Without a database, every endpoint except `/health` returns
`503 {"detail": "db_unavailable"}`.
</Callout>

## Inference

| Method | Path | Inbound format |
|---|---|---|
| `POST` | `/v1/chat/completions` | OpenAI Chat — the canonical shape, no translation |
| `POST` | `/v1/messages` | Anthropic Messages |
| `POST` | `/v1/responses` | OpenAI Responses |
| `GET` | `/v1/models` | — |
| `POST` | `/pi/v1/responses` | OpenAI Responses, verbatim passthrough to OpenAI |

All three inference formats converge on one pipeline: classify → score → decide →
precapture → forward → record outcome. Anthropic Messages and OpenAI Responses
are translated to OpenAI Chat on the way in and back to their own shape on the
way out, streaming included.

`GET /v1/models` is synthesized rather than proxied — it merges the routing
table's tiers (primary and fallback models), any models your LM Studio instance
is serving, and a synthetic `auto` entry. Alongside the standard OpenAI fields
each entry carries `nautgate_provider`, `nautgate_tiers` and `nautgate_unhealthy`.

### Response headers

Every chat response carries:

```
X-Nautgate-Decision-Id     the audit-log join key
X-Nautgate-Provider        who served it
X-Nautgate-Model           what served it
X-Nautgate-Tier            the difficulty band it scored into
X-Nautgate-Score           the score itself
X-Nautgate-Inbound-Format  openai_chat | anthropic_messages | openai_responses
```
