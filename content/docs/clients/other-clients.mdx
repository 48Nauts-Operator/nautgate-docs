## Any OpenAI-compatible client

```bash
export OPENAI_BASE_URL=http://localhost:8090/v1
export OPENAI_API_KEY=ng_…
```

Works with the OpenAI SDKs, Cline, OpenCode, and anything else that lets you set
a base URL. Both `/v1/chat/completions` and `/v1/responses` are served.

## Codex / ChatGPT subscription

Requests carrying a `chatgpt-account-id` header are recognised as subscription
traffic and forwarded to the Codex backend untouched, on the passthrough lane.

<Callout>
Codex's identity comes from the header, not from a token inspection, and the
outcome is recorded with a fixed `codex-subscription` model rather than an
attested one.

Note also that recent Codex versions run the model over a WebSocket rather than
HTTP, which a `BASE_URL` redirect cannot intercept. If your Codex traffic is not
appearing, that is why — capturing it needs a proxy rather than a base-URL swap.
</Callout>

## Pi

Pi's Responses traffic has a dedicated route, `POST /pi/v1/responses`. Point Pi's
`nautgate-oai` provider at it.

### Why it is a separate route

OpenAI **forbids `tools` together with `reasoning_effort` on
`/v1/chat/completions`, but allows it on `/v1/responses`.** Pi's Fusion builder
uses exactly that combination — a high-reasoning model with a large tool set — so
it fails on the normal routed chat-completions path. Pi's native OpenAI provider
already speaks the Responses shape, and this route lets it keep doing so through
the gateway.

The route is **pure routing**: the Responses body is forwarded byte-for-byte to
OpenAI and streamed back byte-for-byte. No translation, no NautRouter, no shared
code. That isolation is deliberate — it means Pi-specific handling cannot affect
`/v1/messages` (Claude Code) or `/v1/responses` (Codex OAuth), which never touch
this path.

Calls are still recorded: session id, prompt excerpt, classification, tool calls
and cache prefix hash are all captured, with the same policy gating as everywhere
else.

<Callout>
A Fusion run that puts several models on the same prompt shows up well in
[head-to-head](/docs/analytics/bench), which correlates real calls by the task
they answered — the comparison is populated by exactly this shape of traffic.
</Callout>

## Your own application

Nothing special is required — it is an OpenAI-compatible endpoint. Use `model:
"auto"` to let the gateway pick a tier-appropriate model, or name a model
explicitly.

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8090/v1", api_key="ng_…")

r = client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": "…"}],
)
```

Set a distinct `agent_id` per application when minting keys — it is what the
audit log, cost breakdown and efficiency scoring attribute against.
